# yt-index

Join the per-clip analyses of a workspace into **one `WORKSPACE/shotlog.json`**: every quality segment becomes a scored candidate the director ranks — one candidate per **content beat** when `describe` split a long segment into beats (each beat keeps the parent's role, motion label and defects, its own `summary`/`interest`/`hero`, and `beat_of`/`beat_id`/`beat_label` say which part of the take it is) — and every **described still photo** becomes one candidate with `media_type: "photo"`. The score fuses a vision content component (0.55) and a quality/motion label component (0.45); a photo's label component is the fixed clean-still prior `0.7` (a still is a perfect hold, no geometry is measured). On an **uncertain** segment the `describe` verdict supplies the effective `role` and `motion_label` (`role_source` / `label_source: "verdict"`), otherwise the geometry labels are kept — except a geometry `accidental`, whose role is final (`role_source: "geometry"`) even when a verdict exists. Every shot carries `score + hook + reason`, the `summary` and `tags` from describe (null / empty when there is no vision) and the `similar_to` links the director uses for diversity. Photos that are similar **and** captured within 30 s of each other form a **burst**: only the best of the burst stays eligible. A self-contained **`WORKSPACE/shotlog.html`** contact sheet is written next to it, one card per shot in score order with a base64 thumbnail (photos included), so the shots can be reviewed on a phone. No model is called. All commands run through `yt <tool>`.

## Step 1: build the shotlog

```bash
yt index --workspace /path/to/workspace
```

- `--workspace` is required. It must hold `quality/` **or** a set of described photos (`ingest.json` plus `describe/<stem>.json` records with `media_type: "photo"`); a photo-only workspace builds a photo-only shotlog without erroring. `DIR/shotlog.json` and `DIR/shotlog.html` are written there, created if missing. The source analyses, clips and photos are never written to.
- `--weight-vision` (default 0.55) and `--weight-labels` (default 0.45) are the fusion weights; `audio_energy` and `text` stay 0.0 until the D2/D4 tools exist.
- `--clips` limits the run to comma-separated 4-digit counters or stem substrings (e.g. `--clips 0072,0081`). Without it every `quality/*.json` is processed.
- `--force` recomputes even when `shotlog.json` is newer than every input it was built from. Without it an up-to-date output is skipped and counted as `skipped` (the contact sheet is not rewritten either).
- `--html PATH` sets the contact sheet path (default `WORKSPACE/shotlog.html`); `--no-html` skips it and the JSON is still written. The contact sheet is written after `shotlog.json`, only when the shotlog was written or `--force` recomputed it.
- On any error it prints one `[error] ...` line to stderr and exits `2` (bad flags, missing `quality/`, unreadable quality file, schema mismatch, `--html` inside the repository) or `3` (runtime failure after work started: disk write). It never asks questions.

## Step 2: read the result

```bash
yt index --workspace /path/to/workspace --json
```

The `--json` output is a single object, e.g. `{"shots": 39, "eligible": 32, "with_vision": 18, "suppressed": 0, "weights": {"vision": 0.55, "labels": 0.45, "audio_energy": 0.0, "text": 0.0}, "wall_time_s": 0.05, "llm_cost_usd": 0.0, "output": ".../shotlog.json", "html": ".../shotlog.html", "skipped": false}`. `html` is the absolute contact sheet path, or `null` with `--no-html`. Read `DIR/shotlog.json` for the full records; it is validated against `schemas/shotlog.schema.json` and written atomically, so a run leaves a complete valid file or none. `llm_cost_usd` is always `0.0` — this tool calls no model service.

## The contact sheet

`WORKSPACE/shotlog.html` is a single self-contained file (no external CSS/JS/CDN; the only JavaScript is the inline `sessionStorage` open-state snippet) that opens offline on a phone. It opens with a summary line (`{pieces} pieces from {clips} clips · {usable} usable · {shaky} shaky · moves: … · scenes: …`, the `moves:` / `scenes:` parts omitted when there are none) and puts the cards behind three collapsed `<details>` sections (no `open` attribute): **Used in the edit** (the shot keys `edit.json` marks `used`, read from `WORKSPACE/edit.json` when it exists), **Kept but not used** (eligible and not used) and **Not usable** (not eligible and not used), each with its count. Inside a section the cards are grouped per source clip (`<section class="clip-group" data-clip="…">` with an `<h3>`), clip groups sorted by name and cards inside a clip **highest score first**. Each card shows a base64 JPEG thumbnail (one frame at the middle of the shot, about 320 px wide), the clip name and `mm:ss.d–mm:ss.d` range plus the shot key, the `summary` and `tags`, the `score` with its `vision` / `labels` components, a `HERO` badge when `hero` is true, an `eligible` / `not eligible` badge (not-eligible cards are dimmed but keep their score position) and the effective `role · motion_label` with the `hook`. The header shows the workspace folder name, the summary line and the `generated_at`. When a clip cannot be opened the card shows a placeholder with the clip name instead of failing the run. The contact sheet's thumbnails are base64 inside this one generated file; the recap's own `thumbs/` folder (the poster and the per-shot JPEGs) is written separately by `scripts/thumbs.py`. The file is generated output in the workspace and is never committed; `--html` pointing inside the repository is refused.

## Photo shots and bursts

Every `describe/<stem>.json` record with `media_type: "photo"` becomes one shot — the pseudo-segment `p1` joined with `ingest.json` `photos[]` for the capture time and file name. The key is `<counter>/p1`, the same convention `similarity.json` uses (`clip_counter(file)` on the photo file name, stem fallback on a repeated counter in file-name order). A photo shot is always role `hold`, motion `static`, `role_source` / `label_source: "geometry"`, `confidence: 0.7`, `media_type: "photo"`, `start_s: 0.0`, `end_s: 0.04` and `defects: []`; it carries `capture_time` (ISO from EXIF, null when ingest has none) and `subject_position` (`{x, y}` in 0..1 from the describe record, null when the photo was skipped or unmeasured). Its `scores.labels` is the fixed `0.7` clean-still prior (no geometry is measured on a still) fused with the usual vision component, so a skipped photo still yields a candidate with the neutral `0.5` vision prior.

**Burst suppression** runs after the overlap rule. Two photo shots whose `similar_to` contain each other and whose `capture_time` differs by at most 30 s are in the same burst; the winner is a member without a spoiling flaw (`eyes_closed`, `blur`, `motion_blur`, `obstructed` in its `defects`, from describe's `photo_flaws`), then the highest `score` weighted by relative `sharpness` (0.7 for the softest to 1.0 for the sharpest of the burst; ties: lower key) and every other member is marked `suppressed_by` the winner key, `eligible: false`, `score: 0.0`. Chains of similar photos resolve to the global best of the burst, so only the best shot of a rapid capture stays eligible. Photos more than 30 s apart never suppress each other, even when similar.

## What the fields mean

- `shots` has one entry per scored unit, in clip order then time order: one per quality segment, one per **content beat** when `describe` split a long segment, or one per described photo. `key` is `<clip counter>/<segment id>` (e.g. `0081/s7`), `<clip counter>/<segment id><beat id>` for a beat (e.g. `0072/s7b1`) or `<photo counter>/p1` for a photo (e.g. `0068/p1`), the same format as `similarity.json`. A beat shot carries `beat_of` (the parent segment id), `beat_id` (`b1`..), `beat_label` (`approach`, `inside`, `exit`, ...) and the beat's own `start_s`/`end_s`; its role, motion label, confidence, uncertainty and defects come from the parent quality segment. A photo shot has `media_type: "photo"`, `segment_id: "p1"`, `start_s: 0.0`, `end_s: 0.04`, `capture_time` and `subject_position`.
- `role`, `motion_label` and `confidence` are the **effective** labels: the vision verdict when the segment is `described` and has a non-null `verdict`, otherwise the geometry values. A geometry `accidental` is the exception — its role is final (`role_source: "geometry"`), while the verdict may still correct its `motion_label` (`label_source: "verdict"`). `role_source` / `label_source` say which won (`verdict` or `geometry`). `uncertain` and `uncertain_reasons` are echoed from quality.
- `score` is the fused number the director ranks by; `scores.vision` and `scores.labels` are the components (`scores.vision` is null when there is no vision data, but the fusion still uses a neutral `0.5` prior for that shot). Not-eligible shots are zeroed. For video shots `labels = clamp(ROLE_BASE + 0.25*confidence - unsteady penalty - defect penalty, 0, 1)` (`scripts/common/scoring.py` `label_score`): steadiness and a defect-free segment add nothing above the base, only the unsteady levels (`unsteady -0.10`, `very_unsteady -0.20`) and real defects (`-min(0.4, sum(value * weight))`, horizon weighted 0.5) subtract; for photo shots `labels` is the fixed `0.7` clean-still prior. `vision = min(1, interest/100 + 0.15 if hero)`, or `0.5` when there is no vision; `score = (0.55*vision + 0.45*labels) / (0.55 + 0.45)`.
- `eligible` is false for an `accidental` (effective role, always — a verdict cannot rescue it), for a confident `setup` / `teardown`, for a photo with a spoiling flaw, and for a suppressed shot (overlap or photo burst); everything else is eligible, including an uncertain setup/teardown, a photo (always role `hold`) and any eligible shot with no vision data (labels only). The director picks only eligible shots.
- `summary` and `tags` come straight from the describe answer (`summary` is at most 12 words, `tags` at most six lowercase tags); on a beat shot the beat's own `summary`, `interest` and `hero` win when present, else the parent segment's. They are `null` / `[]` when the shot has no vision and are what `shotlog.html` shows.
- `peak_s` (D2-12, optional) is the describe `peak_s` of the segment (a beat's own peak on a beat shot, else the segment peak when it falls inside the beat), kept only when it lies inside the shot's `start_s`..`end_s`. The directors centre trimmed cuts on it.
- `hook` names the draw: the vision `subject`, else the first 8 words of the `description`, else `"<role> · <motion_label>"`. `reason` is the plain-words audit trail, e.g. `"approach · interest 80 · hero · travel_forward by geometry · move · clean"` or `"no description · static by geometry · accidental · clean · not eligible"`.
- `similar_to` lists the other keys of every `similarity.json` pair containing this shot, most similar first. `defects` carries the measured defect names from quality. `whip` carries the whip mark from quality (`short_hold` / `deliberate`, null when the segment has none); a shotlog written before this field existed is accepted, and re-running `index` adds it.
- `suppressed_by` is set when two shots in the same clip overlap by more than 50% of the shorter one (the lower-scored is suppressed by the higher-scored), or when a photo loses its burst — similar photos captured within 30 s, where only the best stays eligible. A suppressed shot becomes ineligible with a zero score. The overlap rule does not fire on the current tiling; it keeps the VISION overlap rule alive.
- `media_type` is `"photo"` on photo shots and absent (video) on the others. `capture_time` is the photo's ISO EXIF capture time from ingest (`null` for video shots) and is what the burst window compares. `subject_position` is the photo's main-subject centre in normalised image coordinates (`{x, y}` in 0..1, `null` for video shots or a skipped photo) and later drives the Ken Burns move.

## Notes

- This is the join stage of D1b: it consumes the outputs of `ingest`, `motion`, `quality`, `describe` and `similarity` and produces the file the director ranks by.
- It never cuts, trims or deletes anything; it only scores and links what the other tools measured.
- Audio and text score components are reserved in the schema at zero weight until D2/D4.
