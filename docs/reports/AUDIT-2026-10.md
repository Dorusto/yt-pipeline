# AUDIT 2026-10 — read-only audit of yt-pipeline

Branch `audit-2026-10` from the head of `s60-finishing` (43d89ce). Read-only: nothing changed, nothing committed. Cost of this audit is reported in the ntfy message.

**Summary.** 36 findings: 12 high, 17 medium, 7 low. The code keeps the independence rule (no tool imports another tool) but the agent contract is uneven: `--dry-run`, `--json` costs, exit codes and structured errors are only partly in place. The 2026-10-23 no-personal-setup rule is still broken in code (`inbox.py`), docs and almost every `--help` example. Publishing is where the real-world issues cluster (kit rebuild, metadata prompt, thumbnail, Content ID). Eight issues from the real-clip publish are already queued as GitHub writes and are marked below instead of being proposed again. Everything fits in 12 fix lots of at most 0.8 USD.

---

## 1. Independence

- **F35 (low)** `scripts/music_pick.py:180`, `scripts/shorts_generator.py:295`, `scripts/finish_pip.py:656`, `scripts/eval_rough_cut.py:389`, `scripts/render.py:691` — these tools shell out to another tool's script (`beats.py`, `reframe.py`, `matte.py`, `subs_from_edit.py`) instead of only `scripts/common/`. It matters when one tool is moved, renamed or run from another checkout. Fix: either accept orchestrator-style subprocess calls in a DECISIONS entry naming the allowed set, or move the shared step behind a `common/` helper.
- **F04 (high)** `scripts/publish.py:985` — `--kit` cannot be rebuilt alone: a changed input needs `--force`, which re-runs every step including translation and metadata and overwrites a hand-edited draft. Covered by queued issue "publish kit: rebuild it alone, and link the video instead of copying it".
- The chain tools (`recap.py`, `publish.py`, `mode_b.py`, `serve.py`) only chain station CLIs as subprocesses, which the rules allow. No tool imports another tool's code. Re-run safety is generally in place (`step_outputs_exist`, `--force`, atomic replaces).

## 2. Contract

- **F07 (high)** `scripts/ingest.py` (has `--json` but no `wall_time_s`/`llm_cost_usd`) plus `scripts/notify.py`, `scripts/kdenlive_from_fragments.py`, `scripts/srt_from_fragments.py`, `scripts/reframe.py` — a `--json` summary without wall time and LLM cost breaks the rule that every `--json` reports both. Fix: add the two keys in one shared summary helper.
- **F31 (low)** `scripts/analyze_srt.py`, `scripts/correct_srt.py`, `scripts/daily_summary_srt.py`, `scripts/translate_srt.py` — no `--json` at all (legacy tools). Two of them call an LLM, so an agent cannot read their cost. Fix: add `--json` with the same summary shape.
- **F08 (high)** exit codes do not mean the same thing everywhere: `scripts/mode_b.py` documents 0/1/2/3 (all clear / suspect / incomplete / error), `scripts/music_pick.py` uses 0/1/2, most other tools 0/2. An agent cannot branch on the code without reading each tool. Fix: one table in RULES (0 ok, 1 tool verdict, 2 usage/config, 3 error) and align the outliers.
- Config-error exits are being standardised to exit 2 (`music_pick.py`, S60 lot 8b) but the sweep is unfinished; `scripts/inbox.py` inbox resolution exit codes were explicitly left to this audit. Fix: finish the sweep in the same lot as F08.
- Errors are a clear `[error]` line in most tools; structured `{"ok": false, "error": ...}` exists in only 12 of 50 scripts (**F24, medium**).

## 3. Docs drift

- **F30 (medium)** `README.md:36` — the Workflow section still shows a raw `whisper` command and older steps while `transcribe.py` and `publish.py` exist. Fix: rewrite the workflow around the publish chain.
- **F28 (medium)** `.claude/skills/yt-finish-pip/SKILL.md:110-112` — still describes `finish_pip.animate.jsonl` as keyframe evidence without the `finish_pip.animate.applied` marker (known S60 lot 1d leftover a). Fix: name the marker as the evidence condition.
- **F29 (medium)** `docs/ROADMAP.md:69` — the picture-in-picture line names lots 1, 1b and 1c but not 1d (known leftover d). Fix: add lot 1d.
- **F27 (medium)** `docs/DECISIONS.md:2384` (entry of 2026-10-22, S60 lot 7b) — lot 1d edited this old entry in place (removed the zero-length graphics overlap claim) instead of adding a new dated correction (known leftover c). Fix: restore the entry text and put the correction in a new dated entry.
- **F09 (high)** `docs/guides/user-guide.md:63-108`, `README.md:190-191` and the `--help` examples of most scripts still show personal paths (`<clip-folder>/...`, `<workspaces>/...`, `<projects>/...`) against the 2026-10-23 rule (known leftover b, and much more beyond it). See area 11.

## 4. Human-in-the-loop

- Good: `publish.py` stops for subtitle review (`review` step, `--resume`); `graphics_plan.py` writes every entry `approved: false` for a human to flip; shots/cut review taps record the human answer.
- **F14 (medium)** `scripts/thumbnail.py` — renders one result with no title confirmation before work and no option set. Covered by queued issue "thumbnail: confirm the title first, render 2-3 options, check each render with a vision model".
- **F15 (medium)** `scripts/metadata.py` — the chosen title is parsed from the context note instead of being an explicit input; the model also decides alone on links and pinned comment. Covered by queued issue "metadata prompt: titles, invented links, pinned comment, EN fixed sentences and EN chapters". The attached local patch (not applied) is judged in area 6.
- **F06 (high)** `scripts/analyze_srt.py:300`, `scripts/shorts_generator.py:111,135` — `input()` blocks with no TTY and no `--yes`/flag alternative, so an agent hangs. Fix: move every prompt behind a flag (`--select`, `--video`) and fail with a usage error when the flag is missing and stdin is not a TTY.

## 5. Self-checking

- **F16 (medium)** stale subtitles are not checked: an SRT that ends before the final video is published silently. Covered by queued issue "publish: warn when subtitles do not match the final video".
- **F17 (medium)** `scripts/loudness.py` — `--dry-run` works only with `--fcproj`; there is no measure-only mode for a video file (integrated LUFS + true peak without writing). Not yet queued. Fix: `--measure-only` on the video backend.
- **F03 (high)** `scripts/common/llm.py` — no retry on an empty or non-JSON model response (seen once out of three runs on a real clip). Covered by queued issue "LLM client: retry once on an empty or non-JSON model response".
- Chapter timestamps are validated against the transcript end (`metadata.py validate_chapters`); `graphics_plan.py` retries once on an invalid model answer. Good patterns to reuse.
- Tools that should offer 2-3 options instead of one result: `thumbnail.py` (**F14**), `metadata.py` titles (already 3, good), `music_pick.py` (one choice; `--list` exists, a ranked top-3 would help).

## 6. LLM use

- Model choice per role is config, not code (`config.yaml` `models`, `common/config.py model_for`). Good.
- **F15 (medium)** prompt quality: generic "Name: subtitle" titles, an invented GitHub link, Romanian sentences inside the EN description, RO-only chapters, an AI-sounding pinned comment. Covered by queued issue "metadata prompt: ..." plus the attached patch.
- **Patch judgement** (`.opencode/tasks/AUDIT-2026-10-metadata-patch.diff`, not applied): the direction is right and should be the base of the fix — EN fixed sentences (`MEMBERS_SENTENCE_EN`, `CLOSING_EN`), `title_en` per chapter used by the kit's EN chapters, no invented links, a plain pinned comment, `EXAMPLE NAMES` in the config example. Two gaps: the chosen title should be an explicit `--title` input on `metadata.py`/`publish.py` (the patch only reads it from the Context), and the two fixed channel sentences should eventually move to config with the members line (F26). Fix: implement the patch properly with those two additions.
- **F12 (high)** `prompts/metadata.md:47` hardcodes the channel GitHub URL — a channel-specific value in a tracked file; it should come from config like `channel.members`.
- Failure handling: cost is raised when `usage.cost` is missing (good, keeps the ledger honest), but see F03 for the missing retry.

## 7. Disk and data

- **F04 (high)** `scripts/publish.py:896` — `--kit` copies the final video (about 1 GB) into `publish-kit/`; the same queued issue covers linking instead of copying.
- Originals stay read-only and outputs go to the workspace in the tools checked; step files are written atomically and temp files cleaned up.
- Model weights land in `~/.cache/yt-pipeline/models/` (documented cache, fine).

## 8. Tests

- **F22 (medium)** no test file at all: `analyze_srt.py`, `daily_summary_srt.py`, `kdenlive_from_fragments.py`, `srt_from_fragments.py`, `translate_srt.py` (two of them call an LLM and can be tested with the mock backend).
- **F23 (medium)** a large part of the suite never runs on the build machine: `needs_footage`, `needs_melt`, filmcraft-cli, HyperFrames, reference-material tests, the rembg integration test (OOM) and `test_similarity` (skips when the ONNX model is absent). Fix: one doctor-style test report in CI logs listing what was skipped, so "green" is never read as "all ran".
- Tests use synthetic fixtures only. Good.

## 9. Security and privacy

- `scripts/check_public.py --all` passes (322 files, 0 problems): no secrets, no private IPs, no footage in tracked files. Placeholder key `sk-or-v1-...` in docs only.
- **F32 (low)** `config.yaml.example:21` ships example member names; the queued metadata patch marks them `EXAMPLE NAMES`. Acceptable once the patch lands.
- **F10 (high)** the hardcoded channel URL in `prompts/metadata.md` (see area 6) is the only channel-specific value in a tracked file.

## 10. Web readiness

- `serve.py` can already: upload into the inbox, start a recap, show the run state, serve previews, record shots/cut/shorts review answers, re-edit. A stranger on the tailnet can review and re-edit.
- **F19 (medium)** the publish flow (subtitles, metadata, thumbnail options, kit) cannot run from the browser. Covered by queued issue "web app: run the publish flow from the browser". Missing pieces: the publish steps are CLI-only, and the human review stop needs a web equivalent.

## 11. Independence from the owner (rule of 2026-10-23)

- **F01 (high)** `scripts/inbox.py:30` — `DEFAULT_PROJECTS` defaulted silently to a personal projects folder; the rule requires flag → env → config → error naming the three ways. Fix: `--projects`, else `YT_PIPELINE_PROJECTS`, else `projects.path` in config, else a usage error.
- **F09 (high)** personal example paths across `--help` epilogs and docs: `describe.py:142-146`, `director.py:101-106`, `doctor.py:6-7,74-75`, `edit_to_fragments.py:23-24,58-59`, `explain.py:49-51`, `index.py:84-90`, `ingest.py:51-52`, `llm_director.py:157-161`, `mode_b.py:773-774`, `inbox.py:6-7,87-88`, `shorts_generator.py` prompts, `README.md:190-191`, `docs/guides/user-guide.md:63-108` (`<eval-folder>/...` included) and several skills (`yt-eval`, `yt-export-kdenlive`, `yt-ingest`, `yt-recap`, `yt-render`). Fix: one sweep replacing them with `<trip-folder>`, `<workspaces>`, `<music-library>`-style placeholders.
- **F33 (low)** `CLAUDE.md` "How to run" keeps `<clip-folder>/<clip>/...` examples (historical context file; sweep or mark as Doru's machine examples).
- `agent_watchdog.py:50-53` has personal cache defaults but they are documented and overridable by flags; leave unless the user wants the rule applied literally there.
- A stranger with only the README: after the sweep and F02 (pinned requirements) and F34, yes.

## 12. Agent-usability (issue #66)

- **F05 (high)** `--dry-run` exists only in `agent_watchdog.py`, `finish_pip.py`, `llm_director.py`, `loudness.py`, `notify.py`; the rule asks for it on every tool that writes or calls a paid model (`describe.py`, `metadata.py`, `translate_srt.py`, `daily_summary_srt.py`, `thumbnail.py`, `graphics.py`, `transcribe.py`, `publish.py`, `render.py`, `shorts_generator.py`...). Fix: add it in one sweep, cheapest first.
- **F06 (high)** blocking `input()` (area 4).
- **F07/F31** `--json` cost reporting (area 2).
- **F24 (medium)** structured errors only in 12/50 scripts. Fix: `{"ok": false, "error": ...}` on stderr with the documented exit code.
- **F25 (medium)** `schema_version` is written by 9 scripts; outputs like `beats.json`, `music_choice.json`, `publish_state.json`, `finish_pip.*.jsonl` have no schema and no version. Fix: add `schema_version` and a schema for anything another tool reads.
- Budget flags (`--budget-usd`) exist where an LLM is called through recap; not universal. Exit-code table: see F08.

## 13. Dependencies and reproducibility

- **F02 (high)** `requirements.txt` and `requirements-dev.txt` are unpinned (`opencv-python-headless`, `torch`, `pytest`, ...). Two machines will not build the same environment. Fix: pin exact versions known to work here and refresh deliberately.
- **F11 (high)** silent downloads at first run: `scripts/matte.py:166` `torch.hub.load` fetches RVM weights, `scripts/thumbnail.py:332` rembg fetches BiRefNet. The rule says nothing downloads silently. Fix: a `--fetch-models` step or doctor check that prints what will be downloaded and where.
- **F34 (low)** `scripts/ingest.py:218` calls `ffprobe` with no pre-check; `doctor.py` covers the whole machine but individual tools should fail with an install hint.
- Determinism where no model is involved holds in the tools checked.

## 14. Licences

- `music_pick.py --list` reports licence status per track (S60 lot 8). Fonts ship with SIL OFL notes in the brand kit.
- **F12 (high)** the publish kit does not read the music sources of the edit or keep licence proof for Content ID disputes (real case: a Pixabay track got a Content ID claim from the same artist's licensor). Not yet queued. Fix: the kit lists music files with their licence file, warns when the licensor is known to register with Content ID, and prepares a dispute text and an optional credit line.
- **F36 (low)** SFX tool: planned in S60 lot 3 (`sfx_place.py` + synthesised set), not proposed again.
